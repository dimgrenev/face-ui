# Аудит Face UI — 11 сентября 2026

Этот документ сохраняет исходный общий аудит. Последующие решения по каждому prop,
миграции и более полные проверки ведутся в [журнале индивидуальных аудитов](props/README.md).
Текущий подробный отчёт — [Select](props/Select.md); общая цель ещё открыта.

## Вывод

Основная проблема была в несовпадении трёх контрактов: публичного API, реального поведения и общей визуальной системы. Успешная сборка и галерея этого не обнаруживали. Мембрана, фокус, контролируемое состояние и типографика имели несколько конкурирующих реализаций; часть пропсов декларировала поведение, которое отсутствовало или ломалось в композиции.

Исправления сосредоточены на общих механизмах и подтверждённых дефектах. Добавлены единые Membrane, Trigger, стек слоёв и адаптер нативных форм; удалены глобальные обработчики мембраны, конкурирующие ловушки фокуса, дублирующий типографический проход и фиктивные параметры. Это существенное изменение библиотеки до внедрения, с явно описанной миграцией.

## Рабочая спецификация и границы

- Владелец: канонический `face-ui/`. Потребители: `userface-app`, `userface-site` и обнаруженный в конфигурации синхронизации `defrictor`.
- Цель: согласованная геометрия и композиция, работающий API, корректные формы/клавиатура/слои, предсказуемый жизненный цикл React.
- Публичный эффект: уточнение мембраны, удаление дублирующих Switcher/Popover props, отдельный Table.rowStyle, реальные form props у Select/Date; обновление JSON-контрактов и сценариев.
- Интеграция: сгенерированные снимки обновляются из владельца вместе с lockfiles. Ручное редактирование снимков исключено.
- Инструмент синхронизации workspace также исключает `.playwright-mcp` и сохраняет consumer node_modules. Полная verify-команда устанавливает зависимости из обновлённых lockfiles перед сборками. Раньше sync стирал pnpm links, а lock-only не восстанавливал их.
- План проверки упаковки engine: исправить только внутренние directory specifiers в src/index.ts, сохранив имена публичных экспортов; добавить реальный ESM import в smoke, затем canonical build + smoke, sync и product build. src/index.ts не входит в build-public mapping; browser runtime и build scripts не меняются.
- Дополнительный владелец: `userface-engine/packages/engine/tsconfig.json`. Его наследование от конфигурации потребителя ломало самостоятельную CJS-сборку; конфигурация сделана самостоятельной без изменения runtime API.
- Риск отката/частичного применения: старые продуктовые снимки сохранят прежние DOM/API/поведение. Изменения источника, контрактов, потребителей и lockfiles должны ехать вместе.
- Существовавшие пользовательские изменения в приложении сохранены. Коммитов, публикации и развёртывания в рамках аудита нет.
- Production isolation gate обнаружил три абсолютных пути к checkout в двух существующих app test fixtures. Это mock-данные, а не runtime imports; заменены на нейтральный `/workspaces/component-library` без изменения смысла проверок.

## Концептуальные решения

Мембрана остаётся маленьким явным механизмом, а не системой глобального распознавания интерактивных потомков. Пассивное содержимое и активная граница имеют разные обязательства. Вложенный компонент сохраняет собственную типографику и семантику.

У каждого общего механизма один владелец: мембрана — Membrane, триггер — Trigger, вложенность/дисмисс — layers, reset — useFormReset, browser form proxy — FormValue. Совместимые устаревшие hooks делегируют общему механизму, а не поддерживают параллельную реализацию.

Не удалялись параметры только потому, что их значения по умолчанию совпадают. `children` и `text` представляют rich composition и декларативный контент; native event и semantic callback имеют разные payload. В документации зафиксирован приоритет. Удалены именно конкурирующие смыслы и неработающие обещания.

Для часовых поясов использована поддерживаемая библиотека, а не собственная таблица DST. Поведение `compatible` и точность до минуты описаны в контракте; подробнее — [официальная документация CalendarDateTime](https://react-aria.adobe.com/internationalized/date/CalendarDateTime).

## Миграция и пределы доказательства

См. [актуальное руководство](../../docs.md), раздел September 2026 migration. `scripts/migrate-quality-api.mjs` имеет dry run по умолчанию и `--write`; произвольные JSX spreads и пользовательские обёртки требуют просмотра. Table row presentation нужно мигрировать явно, чтобы не поменять смысл интерфейса незаметно.

Аудит не присваивает библиотеке оценку «выше Radix» и не объявляет отсутствие всех возможных дефектов. Не выполнена сертификация WCAG или ручной полный цикл NVDA/JAWS/VoiceOver и физических touch-устройств. Gallery axe проверяет представленные состояния; продуктовый контент, локальные темы, zoom, большие данные и нестандартные композиции требуют проверки в продукте.

Известные ограничения API теперь обозначены: встроенные английские action labels не полностью локализуются через Date.locale; Date имеет minute precision и фиксированное DST disambiguation; Table не обещает виртуализацию; Upload не включает транспорт; Slider/Rating/Calendar/SegmentedControl не заявлены как native submit fields. Эти возможности не добавлялись как несогласованный набор новых пропсов.

Markdown сохраняет `sanitize-html`. Vite сообщает о его транзитивных Node-oriented CSS parser imports; style attributes запрещены и этот путь не исполняется, browser tests ошибок выполнения не обнаруживают. Замена sanitizer требует отдельной проверки совместимости и безопасности, поэтому самодельный sanitizer в рамках рефакторинга не вводился.

Дополнительный read-only `build-public.cjs --check` в каноническом engine сообщает о четырёх отсутствующих копиях в `public/runtime/engine/`. Это отдельный browser-runtime snapshot за пределами Face UI, не затронутый исправлением npm entry points; его исходники и генератор не менялись. Проверки npm build/smoke проходят; проверка полного browser-runtime snapshot engine остаётся непройденной.

Сайт собрался с существующим предупреждением о local storage driver в production; настройки хранения и развёртывания не менялись. Generated proof-pack сайта обновлён из канонического engine (идентификаторы/хеши и регистр label), без правки бизнес-данных.
