# Calendar: решения по публичному API

Calendar выбирает гражданские календарные дни, независимо от часовой зоны
браузера. Date предоставляет поле с форматированием, формой и явной границей
преобразования instants. Общую сетку, арифметику и клавиатурную навигацию они
используют совместно. Это позволяет держать один механизм без смешивания
ответственности самостоятельного календаря и поля.

## Проверенные решения

| API | Сценарий и решение | Проверенное поведение |
| --- | --- | --- |
| value | Управление выбранным днём или диапазоном из приложения; сохранить | Только ISO YYYY-MM-DD; null очищает выбор; отказ родителя сохраняет принятое значение |
| defaultValue | Начальный выбор без владения каждым обновлением; сохранить отдельно от value | Читается один раз, игнорируется при controlled value; позднее изменение не сбрасывает выбор |
| selection | Один день или последовательный выбор двух концов; сохранить | Discriminated single/range types; single не принимает range; переключение uncontrolled range→single удаляет end без события |
| onValueChange | Единственная граница пользовательского изменения | Один ISO callback на изменение; повторный single выбор тихий; внешнее обновление и смена конфигурации не вызывают callback |
| CalendarRangeValue.start/end | Известные и ещё не выбранные концы диапазона | Оба ключа обязательны; string или null; end-only диапазон завершается с сохранением конца; обратный выбор упорядочивается |
| viewDate | Показать другой месяц без изменения выбранной даты; самостоятельный сценарий | Управляет только месяцем; отказ родителя и обновление не выбирают день |
| defaultViewDate | Открыть нужный месяц при пустом или далёком выборе | Инициализация один раз; игнорируется при controlled viewDate; нет повторного чтения изменённого default |
| onViewDateChange | Согласовать пользовательскую навигацию с внешним календарём | Первый день месяца в ISO; тихие внешние обновления; после release сохраняется принятый месяц |
| min/max | Ограничить допустимый календарный период | Включительные ISO границы для выбора; навигация остаётся ограниченной; годы 1–9999 не превращаются в 1900-е или повторные даты |
| disabledDates | Исключить конкретные дни | По умолчанию запрещённый день разрывает диапазон; endpoints всегда должны быть доступны. Внешние значения сохраняются без коррекции |
| excludeDisabledDates | Бронирование требует доступности всего периода; аналитический фильтр может ограничивать только границы | Только selection="range"; default true; false разрешает запрещённые внутренние дни. Новый выбор через разрыв начинает draft, включая reverse/end-only и устаревший anchor |
| disabled | Приостановить весь календарь | Нативно отключает day/nav buttons, убирает их из Tab; выбор и навигация блокируются общей машиной; внешние значения остаются управляемыми |
| readOnly | Просматривать согласованную дату/период без пользовательских изменений | Сохраняет focus и просмотр месяцев; блокирует click/Enter/Space; не теряет неполный range при снятии состояния |
| labels | Перевод навигации без обёрток и обработчиков вместо компонента | previousMonth/nextMonth меняют реальные имена кнопок; общий словарь Date можно использовать повторно; смена подписи сохраняет focus и view |
| locale | Язык дат, цифры и региональное начало недели | Gregorian арифметика, narrow visual и full accessible weekday names, локальные цифры, live updates без выбора |
| weekStartsOn | Рабочая неделя с началом, отличным от locale | Явное 0–6 имеет приоритет; удаление восстанавливает locale default; заголовки и Home/End согласованы |

Невалидные заданные даты и конфигурация отклоняются с RangeError. Они не
подменяются today и не выключают молча ограничения. Calendar не принимает
JavaScript Date; timezone/valueFormat aliases здесь не добавлены. Приложение
преобразует instant в день в выбранной зоне до передачи Calendar.

Проверки: `assets/__tests__/props-calendar-values.test.tsx`, существующие
navigation/locale suites и `scripts/browser/props-date-civil-arithmetic.spec.ts`.
Полные версии и результаты — в [date-civil-arithmetic.md](date-civil-arithmetic.md).

## Что не закрыто

`className`, ref и DOM/ARIA boundary проверены в [calendar-dom.md](calendar-dom.md):
id/style/hidden/dir/lang/ARIA и native events адресуют существующую group,
callbacks сохраняют внутренний focus tracking, capture может отменять действия.
Nullable defaultValue и readonly disabledDates согласованы с runtime и Date.
Остальные платформенные атрибуты не объявляются индивидуально проверенными.
Доступность диапазонов определена в [range availability](range-availability.md). Локализация подписей
действий, весь alignment и ручная проверка вспомогательных технологий ещё не
проверены полностью. Эта таблица не объявляет весь Calendar завершённым.


## Дополнительная проверка массива ограничений

[date-actions.md](date-actions.md): sparse disabledDates раньше пропускал
отсутствующий элемент, тогда как явный undefined отклонялся. Теперь Calendar
посещает каждый индекс, как Date; unit и три браузера подтверждают RangeError
с Calendar disabledDates[index]. Новый parser или alias не добавлялся.

## Состояния взаимодействия

[calendar-interaction.md](calendar-interaction.md) фиксирует раздельный смысл
`disabled`, `readOnly` и ограничений отдельных дней. Both-state transitions,
controlled refusal, preserved range, нативный Tab и contrast проверены на
React18/19 в трёх браузерах; общий CalendarGrid остаётся механизмом Date.
Range-interior constraints разобраны в [range availability](range-availability.md). Localization и manual AT остаются открытыми.
