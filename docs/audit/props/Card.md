# Card и составные части

Card владеет поверхностью и раскладкой секций. Text владеет типографикой, Membrane — внешним зазором вложенного элемента, Button — действием. Проверка Card не закрывает оставшиеся компоненты библиотеки.

## Решения по корневому API

| Проп | Сценарий и решение | Эффект и доказательство |
| --- | --- | --- |
| `title` | Краткий заголовок стандартной карточки, в том числе перевод или inline React-содержимое. Оставлен как удобный вход в Card.Title. Это не нативная HTML-подсказка. | Создаёт один заголовок; обновление, rich nodes и 0 проверены. false, пустые массивы/Fragments и строки не создают пустую секцию. Для явного уровня heading используется Card.Title с as/variant. |
| `description` | Дополнительное объяснение под заголовком, отдельная роль и типографика. | Создаёт Card.Description; скрытие не оставляет пустой блок. Не дублирует title/content. |
| `content` | Тело стандартной карточки; строки и декларативные описания удобны в Face-документах. | Ненулевое значение имеет приоритет над children. 0 сохраняется; false и пустая строка намеренно подавляют fallback. Длинная строка переносится в пределах карточки. |
| `children` | Произвольная композиция Card.Header/Content/Footer либо fallback тела при использовании convenience props. | Проверены оба режима, приоритет content, повторные рендеры и сохранение keyed DOM/локального значения input при перестановке. При наличии convenience props children трактуется как тело; готовое compound-дерево следует передавать без них. |
| `footer` | Итог, метаданные или действия в конце стандартной карточки. | Строка, React-узлы, массивы и вложенные дескрипторы поддержаны. Исправлены тип `object` в контракте и принудительная полная ширина примитивного Text, мешавшая выравниванию. JSON editor остаётся доступен для сериализуемых форм. |
| `variant` | default — стандартная поверхность, plain — прозрачная композиция, code — фон кода. | Три варианта проверены вместе с геометрией и hover/focus в обеих темах. Вариант не скрывает явно выбранный border. |
| `padding` | Внутренний отступ поверхности: default 7px, control 6px/8px в стандартной плотности, membrane 1px, none 0. | Все значения измерены с каждой комбинацией variant/radius/border. membrane здесь обозначает величину из общего токена, а не второй механизм интерактивной мембраны. Сохраняется для вложенных flush/плотных поверхностей; изменение density корректирует control через токены. |
| `radius` | none для стыкуемых поверхностей, md для карточек, lg для крупных поверхностей. | Реальные радиусы 0/8/12px проверены; не отключают border или padding. |
| `border` | Независимая видимая граница. | Исправлено скрытое отключение при padding=none + radius=none. 72 комбинации проверяют фактическую толщину линии и геометрию. |
| `hoverable` | Подсветка группы, внутри которой есть действия. Заменяет вводивший в заблуждение interactive. | Действительно меняет фон для всех вариантов при hover/focus-within. Отключение после mount возвращает фон и сохраняет фокус потомка. Не создаёт роль, tab stop или обработчик действия. |
| `fullWidth` | Занять доступную ширину либо ширину содержимого. | Исправлено неожиданное центрирование при false. Измерены ширина и сохранение начальной координаты; длинное содержимое ограничено родителем в обоих режимах. Центрирование задаёт родитель или style. |
| `footerAlign` | start/end/between для convenience footer. Переименован из footerLayout по фактическому смыслу. | Строки проверены в start/end; несколько действий — start/end/between, LTR/RTL. В compound-композиции тот же смысл задаётся Card.Footer align. |
| Native attributes/events/ref, `className`, `style` | Настройка root div без второго API для DOM. | Ref/id/ARIA/style/click маршрутизируются на корень. title/content заняты компонентными слотами; input defaults и dangerouslySetInnerHTML исключены. Сам по себе onClick не превращает div в доступную кнопку; действия компонуются настоящими контролами. |

## Составные части

Card.Root — ссылка на тот же Card для единообразного compound-синтаксиса, без отдельной реализации или альтернативных defaults.

| Часть / проп | Решение и проверка |
| --- | --- |
| `Card.Header.orientation` | vertical/horizontal заменяет layout=stack/bar. Смысл совпадает с Bar.orientation. Проверены координаты длинного truncate-заголовка и действий на обеих осях в LTR/RTL, без выхода действий за границы. Визуальный просмотр дополнительно выявил сжатие Edit до E…; теперь Actions сохраняет собственную ширину, а заголовок сжимается. Проверяется scrollWidth/clientWidth именно подписи кнопки при всех трёх align группы, двух направлениях и ориентациях. |
| `Card.Header.children` | Заголовок, описание и действия. Общий resolver не навязывает типографику уже созданным элементам. |
| `Card.Content.children` | Произвольное тело, примитивы или поддержанные дескрипторы. Владеет раскладкой тела, а не содержимым дочернего компонента. |
| `Card.Footer.align` | start/end/between, заменяет layout. Измерены позиции двух controls в LTR/RTL; направление задаётся стандартным dir. |
| `Card.Footer.children` | Действия либо метаданные. Примитив больше не получает принудительный fullWidth, отменявший align. |
| `Card.Actions.align` | Тот же CardAlign для группы действий, размещённой в header/footer или непосредственно в Card. Для видимого выравнивания требуется свободная ширина; between распределяет её между действиями. |
| `Card.Actions.children` | Произвольные настоящие controls. Группа не подменяет семантику действий; нового toolbar role нет. |
| Native props/ref всех частей | Принадлежат div соответствующей секции или реальному Text-элементу. Unit проверяет семь отдельных DOM-адресов; несовместимые input defaults и raw HTML исключены. |

Card.Title и Card.Description используют TextProps без повторного объявления тех же полей. Значения по умолчанию: Title — body, Description — muted; оба fullWidth=true, membrane=true. Default body/muted остаются div, поскольку Card не знает уровня заголовка документа. Явный variant=h3/label и остальные семантические варианты теперь сохраняют выбор Text; раньше Card безусловно навязывал div. Явный as всегда имеет приоритет.

| Унаследованный проп обеих частей | Сценарий / проверка в Card |
| --- | --- |
| `text` | Простая редактируемая подпись, отображается в обоих слотах. |
| `children` | Rich inline-композиция; заданные children вытесняют text. Проверены повторный рендер и отсутствие двойного Text. |
| `variant` | Контекстная типографика и семантика Text; все 14 вариантов проверены с пятью размерами в каждой части. Title сохраняет свою роль выделенного заголовка через font-weight. |
| `size` | Явный размер поверх варианта. Исправлен CSS Title, раньше подавлявший size; измерены пять различных возрастающих размеров. |
| `as` | Явный HTML-элемент с сохранением ref. Проверены h3/label и override span. |
| `icon` | Имя glyph либо React-узел рядом с содержимым. Общая реализация Text, без второго Card-specific renderer. |
| `iconPosition` | Обе позиции измерены в сочетании с inset/membrane для каждой части. |
| `inset` | control — ритм контролов, none — без внутреннего отступа. Измерены реальные padding с каждой стороной иконки. |
| `stretchText` | Расширяет внутренний слот; измерен прирост его ширины отдельно от корня. |
| `fullWidth` | Ширина текстового элемента; false/true дают разные размеры. Не отвечает за позицию всей карточки. |
| `align` | left/center/right остаются API Text; измерены три разных положения текста в каждой части. |
| `membrane` | Включает одну общую Membrane; проверены включение/выключение и отсутствие вложенного дубликата. |
| `truncate` | Длинные компактные заголовки; проверены ellipsis и доступность соседних действий. Текст тела без truncate переносится. |
| `htmlFor` | Связь label с контролом. После исправления семантики работает через variant=label; при as=span не попадает в DOM. |

## Общий декларативный путь

`assets/slot-content.tsx` заменяет разные рендереры Bar/Card. Дескриптор `{ __componentName__, ...props, children }` разрешается только через явный локальный реестр. Его children рекурсивно преобразуются в React-узлы; компонент самостоятельно владеет типографикой и мембраной. Строки верхнего уровня по-прежнему оформляет контейнер. React-элементы передаются без изменения; ключи сохраняются при перестановке массива. null/false/пустая строка не создают коробок. Неизвестные имена и свойства прототипа не создают вымышленных компонентов.

Реестр Card: Text, Button, Icon, Card.Header/Title/Description/Content/Footer/Actions. Это ограниченный договор уже опубликованных Face-сценариев, не общий dynamic component loader. Дополнительные поля дескрипторов имеют тип unknown вместо any; их имена не выдаются за статически проверенные props произвольного компонента. Неизвестное имя даёт пустой результат; диагностика документа остаётся задачей authoring/engine.

Парсер контрактов также исправлен: Object.assign и React wrappers больше не теряют defaults корневого компонента, а вложенные callbacks/helpers не становятся источником ложных defaults. Три регрессии сначала упали, затем прошли.

## Проверки и границы

До исправлений исходные пять browser-сценариев Card падали. Расширенный набор Card: 30/30 прошли в Chromium, Firefox и WebKit на React 18. Две дополнительные unit-регрессии на семантику частей и пустую строку сначала упали, затем прошли; полный `pnpm check` — 303 passed, один React-19-only case skipped. Полные browser-матрицы: 285/285 на React 18 и 285/285 на React 19. На React 19 pnpm check дал 304/304. После проверки diff контрактов устранён лишний alias props в Button, скрывавший его defaults от уточнённого парсера; адресные 14 проверок контрактов/парсера прошли. Синхронизация и сборки потребителей фиксируются в README после завершения.

Файлы доказательств: `props-card.test.tsx`, `props-slot-content.test.tsx`, `prop-extraction.test.ts`, `props-types.tsx`, `scripts/browser/props-card.spec.ts`. Автоматические проверки не означают ручную сертификацию всех screen readers и произвольной пользовательской композиции.

Визуальные рендеры светлой/тёмной темы: `.artifacts/card-light.png`, `.artifacts/card-dark.png`. Первая версия показала сжатую подпись Edit (26px содержимого в 21px слоте), хотя контейнер оставался внутри карточки. Новый assert сначала воспроизвёл сбой; после исправления 30/30 Card cases прошли. Повторная полная матрица React 18 — 285/285, pnpm check — 303 passed + 1 skip. Заключительный React 19 прогон дал 285/285 после устранения гонки ожидания в WebKit-тесте; подробности первого сбоя, 10 повторений и успешных сборок потребителей записаны в README.
