# Bar и BarSection

Bar компонует содержимое и действия. Секции используют один настоящий React-компонент, доступный как Bar.Section и как отдельно импортируемый BarSection. Нет анализа типов непосредственных children, перестановки их в придуманные контейнеры или компонентов-маркеров, возвращающих null.

## Решения по каждому пропсу

| API | Сценарий и решение | Наблюдаемый эффект / доказательство |
| --- | --- | --- |
| `Bar.children` | Обычные узлы, секции, Fragments, массивы и поддержанные дескрипторы. | Авторский порядок сохранён. Keyed Fragments и секции сохраняют DOM и локально изменённые значения при перестановке. Секция внутри пользовательского компонента работает. Ранее эти два сценария падали из-за parent inspection и потери key. |
| `Bar.orientation` | horizontal/vertical для заголовка или вертикальной группы. | Координаты кнопок подтверждают смену оси; вертикальный Bar вмещает текстовые кнопки. Вложенный горизонтальный Bar сохраняет собственную ось внутри вертикального: CSS секций ограничен непосредственным DOM-родителем. Вертикальные секции выравнивают контролы по началу поперечной оси, не центрируют подписи разной длины. |
| `BarSection.align` / `Bar.Section.align` | start/end по основной оси, с учётом dir. | Группа закрепляется у нужного края; её содержимое выравнивается в том же направлении, если группа растянута. Измерены обе оси, LTR/RTL и обе конфигурации grow. align не превращается в пустой переключатель при grow=true. |
| `BarSection.grow` / `Bar.Section.grow` | Заголовок или другая сжимаемая область перед закреплёнными действиями. | false сохраняет собственный размер группы; true занимает оставшееся пространство и ограничивает переполнение этой области. Измерен прирост ширины/высоты независимо от align, ориентации и RTL. Длинный заголовок не вытесняет подпись соседней кнопки. Это не fullWidth: учитывается место, уже занятое другими секциями. |
| `BarSection.children` / `Bar.Section.children` | Связанная группа текста или контролов. | Тот же resolver, что у Bar/Card. Строки и числа получают один Text с общей Membrane; 0 сохраняется, false/пустые строки не создают коробки. React-элементы передаются без изменения. Поле принимает SlotContent, включая вложенные дескрипторы. |
| `ref`, native id/title/ARIA/events, `className`, `style` root и секции | Доступ к собственному div, интеграция и нестандартная раскладка. | Ref/id/title/ARIA/style/click адресуют соответствующий DOM. Секции перестали терять атрибуты при интерпретации родителем. Input defaults и dangerouslySetInnerHTML исключены как несовместимые с контейнером, владеющим children. Style остаётся стандартным способом локального CSS-переопределения. |

Grow ограничивает переполнение своей области. Если внутри неё есть несколько действий, нужно обеспечить им достаточно места либо вынести закреплённые действия в отдельную секцию. Ellipsis не является второй моделью Bar: примитивный текст получает Text truncate; для собственного React-содержимого автор задаёт Text.truncate там, где это необходимо. Пользовательские React-компоненты/провайдеры могут возвращать секцию; дополнительный DOM-контейнер между Bar и Section уже является самостоятельным уровнем раскладки и не получает вертикальные правила непосредственной секции.

Bar — layout, поэтому toolbar role по умолчанию отсутствует. Обычный Tab/Enter сохраняет поведение контролов. Если автор явно выбирает role=toolbar, он задаёт accessible name и управление фокусом; Bar выставляет ориентацию этого осознанно выбранного toolbar. Основание — [W3C APG Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/). Отдельный prop, повторяющий role, не добавлен.

## Удалённые API и миграция

| Было | Стало / основание |
| --- | --- |
| `Bar.LeftEllipsis` | `Bar.Section grow`; за ellipsis собственного Text отвечает truncate. Физическое Left больше не противоречит RTL/вертикальной оси. |
| `Bar.Right` | `Bar.Section align="end"`. Это реальная секция с native props/ref, работающая внутри пользовательских компонентов. |
| `Bar.LeftOverlap` | Удалён. Режим накладывал содержимое под действия, создавал конкурирующую модель раскладки и зависел от порядка встреченных маркеров. Расширенная проверка обнаружила потребителя в site UI FontsSection, пропущенном первоначальным поиском. Там постоянно видимые действия перекрывали название шрифта; теперь название занимает grow-секцию, действия — end-секцию. Узкий контейнер переводит их в отдельные строки, кнопки переносятся. Для намеренного перекрытия вне Bar используется явная CSS-композиция. |
| `.uf-bar__left`, `.uf-bar__right`, `.uf-bar--ellipsis`, `.uf-bar--overlap` | Единая `.uf-bar-section` с data-align/data-grow. Canonical CSS потребителей обновлён, отдельный блок compatibility patches удалён. |
| Дескриптор `__componentName__: 'Bar.Right'` | `__componentName__: 'Bar.Section', align: 'end'`. LeftEllipsis аналогично меняется на Bar.Section с grow=true. |

```tsx
<Bar>
  <Bar.Section grow><Text truncate>Workspace title</Text></Bar.Section>
  <Bar.Section align="end"><Button text="Publish" /></Bar.Section>
</Bar>
```

Отдельный импорт BarSection и compound Bar.Section — ссылки на один компонент, без отдельных defaults или веток поведения. FeldChildDescriptor остаётся именем существующего type alias для общего SlotDescriptor; его __componentName__ разрешается через явный реестр Text/Button/Icon/BarSection/Bar.Section. Дополнительные поля unknown, не any. Неизвестные имена не создают выдуманных видимых компонентов.

## Рабочая спецификация и проверки

Цель — одна модель секций с естественной React-композицией, сохранением key/state и логическим направлением. Владелец — canonical face-ui; потребители app/site/Defrictor. Миграция охватывает canonical JSX, JSON/scenario generators, типы, JSX app/site и app runtime manifest. Снимки обновляются только package-sync. Риск неполной миграции — старые marker-имена больше не разрешатся и потеряют содержимое.

Регрессии: props-bar.test.tsx, props-slot-content.test.tsx, props-types.tsx, props-bar.spec.ts. Две новые unit-регрессии сначала упали; после исправления совместный Bar/slot набор дал 12/12. Browser-набор — 21/21 (7 сценариев × три движка), включая grow × align × orientation × dir, сохранность подписи действия и вложенные Bar. Первый новый тест вертикального выравнивания показал центрирование кнопок разной ширины; принят и реализован общий начальный край контролов. Старый CSS-helper в governance-тесте находил суффикс чужого селектора; lookup теперь проверяет начало селектора.

Обязательная проверка этой партии: pnpm check, полные browser matrices на React 18/19, package-sync:check, app desktop:build, site build, Defrictor check:ui/build. Текущие результаты записываются в README после завершения. Автоматические проверки не равны сертификации произвольных пользовательских деревьев или всех assistive technologies.

Визуальная проверка выполнена на `.artifacts/bar-light.png` и `.artifacts/bar-dark.png`: длинные LTR/RTL заголовки, закреплённая подпись действия, пользовательский компонент секции, горизонтальная панель внутри вертикальной, общий начальный край и нижняя группа. Лишней типографики/мембраны и перекрытия действий на этих рендерах нет. Canonical pnpm check: 305 passed + 1 React-19-only skip; React 19 pnpm check: 306/306. Полные browser matrices: 291/291 на React 18 и 291/291 на React 19. App desktop:build, окончательная site build, Defrictor check:ui/build, proof-pack и production-isolation прошли. Снимки синхронизированы; финальное обновление журнала переносится отдельно штатным package-sync.

Первая site build обнаружила пропущенный packages/userface-site-ui. Поиск расширен на все исходники продуктов, мигрированы JSX и пять CSS-модулей. Проверка реальных FontsSection/TopTabsAccordion при viewport 1200 px и контейнерах 1000/520/320 px воспроизвела исчезновение названия (width=0). Media query заменён container query; Chromium/Firefox/WebKit прошли проверки ширины названия, сохранности подписей действий, Edit и раскрытия/выбора вкладки. Скриншоты `.artifacts/bar-site-1000.png` и `bar-site-320.png` просмотрены. Этот локальный интеграционный стенд — проведённая QA, не постоянный CI-тест сайта.
