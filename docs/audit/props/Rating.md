# Rating: индивидуальный аудит пропсов

Rating теперь различает выбор личной оценки и показ среднего результата. Ввод
использует нативные radio inputs; `readOnly` показывает точное измерение с ролью
meter. Оба режима используют один renderer звезды и стандартную Membrane.

В каталоге был реальный сценарий средней оценки, представленный через `disabled`.
Это делало результат недоступным для редактирования, но оставляло семантику формы,
затемнение и округление до шага ввода. Отдельных живых Rating-потребителей в исходниках
app/site/Defrictor вне сгенерированных пакетов не найдено. Обновлены оба сценария
каталога: ответ пользователя и средняя оценка marketplace.

## Решения по каждому параметру

| Параметр | Сценарий и проверяемый эффект | Решение |
|---|---|---|
| `value` | Контролируемая оценка; отказ/принятие родителем, внешние обновления | Конечное число в 0..max. Ввод округляет до шага, readOnly сохраняет дробь. Внешние изменения тихие. При освобождении управления сохраняется последнее принятое значение |
| `defaultValue` | Начальная оценка в форме, нативный reset | По умолчанию 0. Поздние изменения игнорируются; reset восстанавливает исходное значение в текущих границах. Отменённый reset сохраняет ввод |
| `max` | Короткая шкала на 5 или 10 звёзд | Целое 1..10, по умолчанию 5. Невалидный max отклоняется до выделения элементов. Не используется как произвольный диапазон числового ввода |
| `allowHalf` | Пользователь может поставить 2,5 | Сохранён для шага ввода 0,5 вместо 1. Половинки — полноценные цели ≥24 CSS px, с общим изображением звезды. Точность readOnly от него не зависит |
| `readOnly` | Показ среднего 4,2 из 5 | Добавлен. Meter, точное число и дробная заливка, без редактирования, Tab-остановок, preview, затемнения и required-валидации. Именованное ненулевое значение может участвовать в форме |
| `disabled` | Временно недоступный ввод или заблокированная оценка | Сохранён. Оценка видна, редактирование/фокус/отправка отключены, затемнение применяется один раз. Нативный disabled fieldset также работает |
| `label` | Видимая неинтерактивная подпись | Сохранён. Rich text и 0 поддерживаются; пустые строки, пробелы, false, пустые массивы и фрагменты не создают пустой отступ и не блокируют имя |
| `ariaLabel` | Дубликат нативного имени, ранее блокировавшийся пустым label | Удалён; использовать `aria-label` / `aria-labelledby` |
| `aria-label` | Имя без видимой подписи или явное переименование | Передаётся на семантический корень; непустое значение имеет приоритет над label |
| `aria-labelledby` | Подпись в заголовке/соседней области | Наивысший приоритет имени; собственные label ID стабильны и уникальны |
| `formatValue` | Локализованные названия вариантов и описание среднего | Добавлен один callback `{value,max} => string`. Непустой текст; по умолчанию `2.5 stars`, для 0 `Not rated`. Форматирование не меняет FormData или числовое значение |
| `onValueChange` | Сохранение пользовательского выбора | Один `{value}` на изменение. Повторный выбор, reset и внешние обновления тихие. Отказ родителя оставляет принятое значение, но не мешает навигации фокуса |
| `name` | Ключ оценки в нативной форме | Добавлен. Только выбранное ненулевое значение отправляется. Без имени компонент не создаёт скрытый сгенерированный ключ. Независимым Rating в одной форме нужны разные имена |
| `form` | Контрол находится вне элемента form | Добавлен. Работают отправка, required и reset, включая форму, расположенную позже в DOM |
| `required` | Обязательный ответ перед отправкой | Добавлен для редактируемого рейтинга с непустым name. Использует нативную валидацию; readOnly/disabled не блокируют отправку |
| `autoFocus` | Начальный фокус в форме | Добавлен. Только при монтировании, на выбранный/первый доступный вариант. Последующие изменения режима не перехватывают фокус |
| `membrane` | Общие отступы и зоны нажатия | Добавлен. Каноническая Membrane у вариантов и подписи; padding активирует нативный input один раз. Переключение сохраняет DOM, фокус и оценку |
| `className`, `style`, `id`, `dir`, `lang`, `title`, `data-*`, описания и события | Интеграция в интерфейс | Нативные атрибуты передаются на корень. События всплывают; отмена клика/capture/клавиши учитывается |
| `ref` | Фокус/измерение корня и жизненный цикл | Единый стабильный composed ref с поддержкой callback cleanup React 19 |

Семантические role/ARIA значения принадлежат компоненту и не могут расходиться с
визуальным значением. Произвольные children/contentEditable исключены из API.
Callback-функции присутствуют в TypeScript API; JSON-контракты по общему правилу
библиотеки не сериализуют исполняемые обработчики.

## Поведение и оформление

Повторный выбор больше не снимает оценку. Это согласуется с моделью
[radio group](https://www.w3.org/WAI/ARIA/apg/patterns/radio/): группа выбирает один
вариант. Стрелки перемещаются от сфокусированного варианта и циклически обходят
шкалу; горизонтальное направление учитывает RTL. Home/End выбирают первый/последний
вариант. Space использует нативную активацию. При уменьшении max/удалении половины
фокус восстанавливается, если его элемент исчез; внешнее изменение оценки не
перетягивает фокус с сохранившегося элемента.

Ноль означает отсутствие оценки: ни один вариант не выбран, FormData пуст.
Приложение может явно сбросить контролируемую оценку в 0 или использовать reset
формы с исходным 0. Отдельный не запрошенный сценариями проп `clearable` не добавлен.

Граница max=10 — решение этой дизайн-системы, а не требование ARIA. Длинные числовые
шкалы удобнее выражать Slider/Input; [APG также рассматривает slider для рейтинга
с большим числом вариантов](https://www.w3.org/WAI/ARIA/apg/patterns/slider/examples/slider-rating/).

Заливка отражает текущий preview целиком и не сохраняет старые закрашенные звёзды
правее него. Touch не оставляет hover, клавиатура очищает нерелевантный preview.
Дробь вырезается по границам рисунка общей иконки, с учётом её оптических полей:
даже небольшое ненулевое значение имеет видимую заливку. В RTL она начинается справа.
Половинки не разрывают рисунок; переносы происходят целыми парами. Светлая/тёмная
темы, узкая область, zoom, длинные подписи, focus-visible и forced colors проверяются
в браузерах. Ненужные анимации не добавлены.

Удалена Rating FSM: она повторяла нормализацию, держала неиспользуемое half-состояние
и не имела других потребителей. React владеет принятым значением и preview, а формы,
активация и валидация опираются на нативные controls.

## Миграция

```tsx
<Rating
  label="Насколько полезен ответ?"
  name="helpfulness"
  required
  allowHalf
  formatValue={({ value, max }) => `${value} из ${max} звёзд`}
/>

<Rating
  value={4.2}
  readOnly
  label="Средняя оценка"
  formatValue={({ value, max }) => `${value} из ${max} звёзд`}
/>
```

`ariaLabel` заменить нативным именем. Для среднего результата заменить `disabled`
на `readOnly`; `allowHalf` для отображения дроби не требуется. Max должен быть целым
1..10. Код, рассчитывавший на снятие выбора повторным нажатием или Home→0, должен
явно управлять сбросом.

## Доказательства и границы

До изменений сохранены исходники и 10 диагностических случаев (8 failures / 2 passes).
Регрессии: `assets/__tests__/props-rating.test.tsx`, отрицательные публичные типы,
shared browser cases `scripts/browser/rating-cases.ts`, реальные generated gallery
и собранные app/site пакеты. Итоговые команды, результаты React 18/19, визуальная
проверка, drift review и продуктовые сборки фиксируются в
`.artifacts/rating-integration.md`.

Браузерная проверка ARIA и axe не заменяет ручное прослушивание всех скринридеров;
такой уровень проверки здесь не заявлен. Общий аудит библиотеки продолжается.
